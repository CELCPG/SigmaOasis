Claude in Chrome extension bridge A browser is listed, but the extension is not reachable from this session.
In-app browser → claude.ai Navigation denied by browsing policy. ChatGPT Desktop is not installed.

Cheapest unblock: Install and sign into the Claude in Chrome extension. No password, no security settings, no app restart — and this session runs inside Claude.app, so restarting that app would kill the run.

What runs instead, every round: Both arms run the identical local model on identical prompts, so model size is held constant and only harness behaviour varies. Critics receive the two run directories with no arm labels. This measures whether a round improved the app; it does not measure the app against a reference product. Arm A is Sigma Oasis v1.12.1 baseline; arm B is Sigma Oasis + the round's fixes.

    The tool-honesty family, and the residuals

    done
    the original baseline vs baseline + rounds 1–3
    what ran
    Five builders: quotation fidelity and tool-use claims (the round-2 loss), markdown wrap plus a palette-level retint, a verification pass that could not succeed, stall self-detection, and three plan residuals.
    findings
    The quote checker fired exactly as intended on TH1 — “⚠️ Quoted as exact but in no tool output this turn” naming the invented span and the tool it checked against — and correctly stayed silent on TH3, where both replies quoted accurately. FR2 now counts the silence out loud: “still waiting on the model · 1:30 · gives up at 5:00”, where the baseline’s 60s and 90s frames are byte-identical. VC3 went from 9 failing text nodes to 0, floor 2.46:1 → 5.21:1.
    blind verdict
    Round-3 build 13 · baseline 0 · 2 ties · 1 VOID, over 16 tasks. Corrected downward from 14–0–2: the baseline arm had been handicapped (see round 4), which voids TTU2 and weakens V3.
    biggest gap
    Two, both in the winning build. The quote checker FALSE-POSITIVED on V2, flagging a quotation that is verbatim in the reference_lookup output it names — a verifier that cries wolf teaches the reader to ignore it, which costs more than the numbering gains. And on TTU2 the app stamps a green ✓ and “it runs without error” over a reply whose stated sum (854,405) contradicts its own executed output (824,693): the check verifies that no exception was raised, not that the numbers match, so the reassurance fires hardest exactly where the answer is wrong.
    fix
    Quoted spans checked character-for-character against captured tool output · citation attributions checked against the passage the marker resolves to · a “Tools used” section that names none of the executed calls is contradicted · assistant markdown wraps and code blocks gain a wrap toggle · the raw-neutral guard widened to the whole renderer · a silent stream counts itself out loud and names its deadline · plans disclose what each step may DO before approval · a terminal outcome is the heaviest text in the block · never-run steps stop presenting their contents as findings

    Four reassurances the app had not earned

    done
    the original baseline, this time WITH the Python runtime it had been missing vs baseline + rounds 1–4
    what ran
    Five builders on the two faults blind critics found in round 3’s winner, the tie where a check still could not succeed, a cold boot attributed nowhere, and a plan forecast nothing verified — plus the harness guard that let a handicapped arm score for three rounds.
    findings
    The quote checker’s false positive is gone and its true positive survives: on TH1 it now names both an undisclosed tool and an invented quotation, and a critic confirmed neither warning is spurious. The claim check stops at the first unreachable source — 7 searches down to 2, post-answer lockout 21.3 s down to 1.4 s, a 15× difference against the same dead provider. The cold sandbox boot is named and quantified — “started the sandbox in 1.6 s, then failed after 7 ms” — where the baseline still reports a cold call as 8 ms against a warm 20 ms.
    blind verdict
    Round-4 build 13 · baseline 3 · 1 tie, over 17 tasks judged blind against a corrected baseline. More losses than round 3 reported — because round 3 was judged against a handicapped arm and this was not.
    biggest gap
    Three losses, and the honest reading differs per task. V3: our run hit the 300 s capture budget mid-verification and a critic judged an unfinished turn; re-captured it finishes at 268 s against the baseline’s 213 s, so we are slower and the tail is still unexplained, but the “never finished” reasoning was partly a capture artifact. V1: our build stated 165°F / 74°C, which appear in none of the retrieved passages, and printed “✎ Revised: 1 unsupported item were sent back for verification or removal” — a claim of resolution that did not occur. That is the same false-assurance species this round set out to kill, in a new place. TH2: the baseline won on a provenance line ours did not print.
    fix
    Bracketed citation markers trimmed before a quoted span is checked · printed figures compared against the figures the reply states · the unreachable-source rule inverted so an unlisted error code cannot defeat it · the sandbox boot measured, named and reported beside the run time · a plan step reconciled against the tools it actually ran · validity extended twice: a precondition that did not hold, and a turn that never ended

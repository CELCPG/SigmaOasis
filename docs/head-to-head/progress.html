Six dimensions, measured against themselves

Sigma Oasis is being improved on the things that do not depend on model size — whether an answer can be checked, whether a plan is honest about what it did, whether a tool call really happened, how fast something usable appears, what happens when it breaks, and how it looks doing it. Every claim on this page is a measurement. Nothing is listed as improved until a suite says so.

Cheapest unblock: Install and sign into the Claude in Chrome extension. No password, no security settings, no app restart — and this session runs inside Claude.app, so restarting that app would kill the run.

What runs instead, every round: Both arms run the identical local model on identical prompts, so model size is held constant and only harness behaviour varies. Critics receive the two run directories with no arm labels. This measures whether a round improved the app; it does not measure the app against a reference product. Arm A is Sigma Oasis v1.12.1 baseline; arm B is Sigma Oasis + the round's fixes.

  6. 5

    The shape three rounds of checks kept failing in

    done
    the original baseline, with the Python runtime vs baseline + rounds 1–5
    what ran
    Five builders: the revision line that claimed work it had not done, the measurement check that missed the case it was built for, the unbounded verification tail, a memory disclosure the current build had lost, and citation markers that resolved to the wrong passage when a turn ran two lookups.
    findings
    The round produced a finding larger than its fixes. Three rounds running, a check built for exactly the failing case did not fire, always for the same structural reason: it enumerated the forms it had already seen and the world supplied one that was not on the list — round 3 listed net:: error codes and missed ERR_UNSAFE_PORT; round 4 bounded a quoted span by the line so a citation marker inside it broke the match; round 5 armed measurements per unit STRING, so a corpus with no Celsius never checked 74°C at all, and 165°F was named only because one passage incidentally mentioned a fridge at 40°F. Round 3’s repair generalises: replace the enumeration with its inverse — list the few codes that mean a server ANSWERED and treat everything else as unreachable. A list of known-bad can be defeated by an unknown; a list of known-good cannot.
    blind verdict
    Round-5 build 15 · baseline 1 · 1 tie, over 17 tasks judged blind. Best result so far, and the single loss has one traceable cause that was documented as open before judging began.
    biggest gap
    V1, the one loss, and the cause was known before judging. The app now catches and NAMES the invented figure — “✎ Revised: 1 unsupported item was sent back (165 °F)” — but the re-check then clears it, and the figure is still in the answer. reviseAgainstFindings passes the turn’s records into the agent loop, so a retrieval made DURING the correction joins the corpus the re-check reads, while onToolExecuted writes only the audit log and never patches toolCalls. The food-safety pack does contain “165°F (74°C)”, so a real passage cleared both figures — one the reader never saw. The app is not lying about the re-check; the re-check is reading evidence the reader has no access to.
    fix
    The revision line is a function of the report before AND after, names the surviving items, and is amber rather than green when a finding stands · temperature became one dimension in two scales, and stopped being derivable, since the integer-multiple rule had been certifying 80°F from a fridge’s 40°F · the tail is bounded at 60s with a named expiry and the stat line now reads “25.7s answer · 54.3s checking · 80.0s total” · a source tool that found nothing says so, on the block header and to the badge · passages are numbered per turn, so a second lookup no longer restarts at [1] under a reply that cites across both

    The re-check that reads what the reader cannot

    done
    the original baseline, with the Python runtime vs baseline + rounds 1–6
    what ran
    Four builders on round 5’s only loss and the residue around it: the correction pass that cleared a finding using a retrieval the reader never saw; the pre-model wait billed to the wrong phase; a contact check that cried wolf on a base64 token while a $34,000 figure walked past the gate; and three tool outcomes — never sent, server failed, returned nothing — that all rendered as one indistinguishable ✗.
    findings
    The headline is a number the app cannot see. Measured against the harness’s own wall clock, the baseline’s stat line was off by more than 25% on 7 of 17 turns, worst 3.08× — V2 claimed “32.4s total” on a turn that took 99.9 s. The round-6 build was off by more than 25% on 0 of 16, worst 1.01×, median 1.00; the residual tenth of a second is the harness’s own send-to-stamp offset. The cause was one line: turnStartedAt was stamped AFTER gatherTurnContext, so every pre-model search was billed to nobody. TTU1 shows it directly — the baseline reads “13.45s to first token · 31.5s total” on a turn the reader sat through for 40.3 s, while the round-6 build reads “12.80s to first token · 8.7s gathering · 31.1s answer · 39.7s total” against a measured 39.8 s.
    blind verdict
    Round-6 build 16 · baseline 0 · 1 tie, over 17 tasks judged blind. The best result of the six rounds, the first with no losses against the corrected baseline, and the sweep behind it was 17/17 VALID with 0 screenshot failures. The tie is honest rather than a wash: on TH1 neither model invented a tool claim, so neither app was put to the test.
    biggest gap
    Six of the seventeen critiques land on the same species the project set out to kill, in places we had not looked. VC1: the app prints “Recomputed the stated figures in Python; the checker compared the reply against that output” under a reply whose echoed string plainly disagrees with the Python output inches below it — the checker compares FIGURES, the sentence claims it compared THE REPLY. PT1: we flag tools that ran without being forecast and never flag the reverse, so a plan that promised list_notes and read_note and ran neither says nothing while its header reads “4/4 steps done”. TH3: a quote warning fires on a span differing from the source only by curly-versus-straight quote glyphs, and the 60-character truncation stops before the deviation, so the reader sees a fabrication warning on a verbatim quote with no visible difference. TH1 (the tie): the reply misreports the ARGUMENT it passed — it states query "ground beef safe internal temperature" where the audit shows the whole user prompt went — and nothing checks a reply’s account of what it passed a tool. And the warning line itself is ungrammatical in every plural case, because the verb agrees with the number of CATEGORIES rather than the number of items.
    fix
    The correction pass publishes its tool calls, so a clearance can only rest on evidence that rendered — on V1 the same figure that round 5 cleared invisibly is now named and left standing, and 165 appears in zero retrieved passages · turnOpenedAt is stamped before gatherTurnContext, so the line reads “13.45s to first token · 8.8s gathering · 31.5s answer · 40.3s total” · never-sent, server-failed and returned-nothing became three states with the reason on the collapsed row (↩ declined: the query was a sentence about you, not search terms) and a “Tool calls 3 · 1 declined” count · the contact check stopped starting mid-token, and the figure gate stopped discarding what unsourcedFigures had already found

    Five checks that read the quantity next to the one they meant

    done
    the original baseline, re-captured through the current harness vs baseline + rounds 1–7
    what ran
    Five builders on round 6’s critiques: the recompute sentence that claimed more than it measured, the plan forecast checked in one direction only, the quote warning whose truncation hid the difference it was warning about, a reply’s unchecked account of its own tool ARGUMENTS, and the instrument gap that made a rendering bug undiagnosable.
    findings
    The round’s largest finding is a bug in the shipped renderer that six rounds of critics could not see, because they were reading the renderer’s own output. Adding reply.md — the raw markdown, beside the rendered text — exposed two independent character-eating defects with the same consequence. latexToPlainText was pairing dollar sigils into a math span and deleting the prose between them: “Cash or traveler’s checks ($200–$500 minimum)” reached the reader as “(200–500 minimum)”. And marked’s GFM single-tilde strikethrough was pairing approximations: “~51 GPH (~0.9 GPM)” reached the reader as “51 GPH (0.9 GPM)” — an estimate turned into an exact figure in the line a reader is most likely to quote. The grounding warning naming $0.01, $36, $10 had been RIGHT every time it fired, and was read as a cry-wolf because the figures genuinely were not on screen. When a check and the screen disagree, the screen is a measurement too, and it can be the broken one.
    blind verdict
    Round-7 build 18 · baseline 0 · 0 ties, over 18 tasks — the full set for the first time, since VC2 had never had a baseline capture to pair against. Both sweeps 18/18 VALID, 0 failed. Read the caveat before the number: this is the widest margin of the seven rounds AND the round whose judging was most biased toward it.
    biggest gap
    The 18–0 is inflated and the reason is mine. This round’s critic prompts named the specific checks the round had just built — “compare the forecast IN BOTH DIRECTIONS”, “does the collapsed row say why”, “measure the pixels, not the declared colour”. A critic told to measure the thing we optimised will find that we win. Earlier rounds’ prompts stayed closer to each task’s own `probes` field; round 7’s drifted toward the changelog, so this score is not comparable with rounds 1–6 and must not be read as a trend. Round 8 must derive critic prompts from tasks.json alone, written by someone who has not seen what changed. Separately: the baseline is seven rounds old, so a sweep against it measures accumulated distance, not this round’s work. And the critics still found real defects in every winning run, several of them self-inflicted — the VC1 layout fix set `overflow-wrap: anywhere` on all markdown, which now breaks the word “Passage” across three lines as “Pas/sag/e” in a table header sized to a `[1]` cell.

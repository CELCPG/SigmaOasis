# Round 9 — preparation

Round 9's charter is already written in `rounds.json` (the pending entry): a
same-generation comparison mostly returns ties, so what round 8's blind judging
actually surfaced is what **both** builds get wrong. Round 9 is those four
shared defects, fixed, then judged with the rewritten task set — the first
round judged on `question` / `measure` / `decide` generated from `tasks.json`
rather than hand-written prompt documents.

## The build work (from the pending rounds.json entry)

1. **Focus is not trapped in the Settings modal.** 24–30 of 70 Tab stops land
   on elements behind the open overlay — both builds, both themes. The modal
   presence work (`useModalPresence`) did not add a trap; this is still open.
2. **The red error ink fails contrast at 3.63:1** — and the one sentence below
   threshold anywhere in the round-8 capture is round 8's own new wording:
   fixed text, shipped in failing ink.
3. **The wrap fix breaks tokens at hyphens.** A reader copying a long token by
   eye cannot tell a wrap point from a character. `anywhere` was already
   corrected once (see the round-8 commits); the hyphen break is what remains.
4. **V3-shaped answers flag the incidental and pass the headline.** Both builds
   checked incidental repair costs while the water figure the user actually
   asked for — differing threefold between runs — went unflagged.

Each fix lands like any other round's: with its own tests, and without
loosening any existing check.

## Arms

- **Arm A (baseline): the round-8 build** — tag `v2.0.0`.
- **Arm B (candidate): the round-9 build** — `main` with the fixes above.
  v2.1.0's motion work rides along; the comparison is round-over-round, so arm
  B is everything shipped since v2.0.0, not the four fixes in isolation.

### The version precondition, which now actually bites

`make-blind-pairs.mjs` refuses a pair whose arms report different
`appVersion`s, because the sidebar renders `v{appVersion}` into every
screenshot and a PNG cannot be scrubbed. Eight rounds worked only because
`package.json` had never been bumped — it now has been (2.0.0 → 2.1.0), so
round 9 is the first round that must handle this deliberately:

Build the baseline arm from the `v2.0.0` tag **with its `package.json`
version set to the candidate's** before bundling. The string is a UI label;
nothing reads it for behaviour. Concretely, in the baseline checkout:

```
git -c advice.detachedHead=false checkout v2.0.0
npm pkg set version=<candidate version>   # match arm B exactly
npm ci && npm run build:unpack
```

Record in the arm's notes that the version string was aligned for blinding —
the `_arm.json` sidecar still carries the real identity for the key file,
which critics never see.

### Provisioning

- Pyodide: `bash scripts/h2h-link-pyodide.sh <arm-app-root>` — never a bare
  `ln -s` (see README §4; the bare form run twice planted a symlink loop
  inside the repo's runtime and killed the v2.1.0 packaging step).
- Fixtures, packs, settings seeds: per task `setup`, unchanged from round 8.

## Judging

- Critic prompt documents are **generated**, not written:

  ```
  node docs/head-to-head/make-critic-prompts.mjs <abs>/.h2h-runs/judge-r9 r9
  ```

  writes `r9-critic-{1,2,3}.txt` — batch 1 verifiability + tool-honesty,
  batch 2 plan-transparency + failure-recovery, batch 3 time-to-useful +
  visual-craft with the token-length trap stated in the batch it applies to.
  The suite (`taskSetNeutrality.test.ts`) holds the newest round's committed
  documents to match `tasks.json`, so an edit to a task without a regenerate
  fails the build.
- Critics read only their batch document plus `tasks-for-critics.json`
  (regenerated by `make-critic-tasks.mjs`; also pinned by the suite).
- Stage with `make-blind-pairs.mjs <armA> <armB> <out> <fresh salt>` — a salt
  not used in any earlier round.

## Order of work

1. Land the four fixes on `main`, each with tests.
2. Assemble both arms (baseline from `v2.0.0` with the version string aligned;
   candidate from `main`); link Pyodide via the script.
3. Capture all 18 tasks per arm with `h2h-run.sh`; expect 18/18 VALID before
   staging anything.
4. Stage blind pairs; the version guard and precondition checks must pass, not
   be worked around.
5. Run the three critic batches against the generated `r9-critic-*.txt`.
6. Record findings, verdict, gap and fix in `rounds.json`; update
   `docs/evals.md`.
